# 7 种打包方式（含副业档 + AI 辅助档）

**核心原则**: 跑单往往不是价格问题，是打包方式错了。同一份交付物，换个打包方式，客户感知价值完全不同。

---

## 模式 1: 一次性交付（Deliverable）

**形态**: 客户给钱 → 你做完 → 交付 → 结束

**适用场景**:
- 客户明确说"就这一次"
- 客户有验收人 + 明确范围
- 交付物可独立验收

**报价公式**:
```
价格 = 工时 × 人日单价 + 风险溢价（10–30%）
```

**优点**:
- 简单，结算清晰
- 利润率可控

**缺点**:
- 没有复购
- 客户付钱后觉得"就这？"，满意度低
- 客户后续需求再找你，可能按"新单"重新谈

**常见错误**:
- 范围没切清楚 → 客户反复加需求
- 没约定"验收后修改几次" → 无限返工

---

## 模式 2: 能力转移（Transfer）

**形态**: 你交付的不是"结果"，是"客户自己能做的能力"
- 交付物 + 文档 + 培训 + 模板 + 工具
- 客户学会后自己可以复用

**适用场景**:
- 客户说"以后还要调试/维护/更新"
- 客户问"能教我吗"
- 客户业务会持续，但不想每次都付费

**报价公式**:
```
价格 = (一次性交付价) × 1.5–2.5
```

**为什么更贵**:
- 文档成本（用户手册、操作指南）
- 培训成本（讲解、答疑、陪练）
- 模板/工具成本（可复用资产）
- 风险（教会徒弟饿死师傅）

**优点**:
- 客户感知价值高（一次付费，长期受益）
- 降低后续纠纷（客户自己能处理小问题）
- 复购概率高（客户离不开你）

**缺点**:
- 初期投入大
- 客户学会后可能真的不再找你

**关键技巧**:
- 能力转移不是"全教会"，是"教会 80%，留 20% 让你继续接"
- 文档要"傻瓜化"，不能假设客户有基础
- 培训要"分阶段"，避免一次讲太多

---

## 模式 3: 订阅服务（Subscription）

**形态**: 按月/季度/年付费，享受持续服务

**适用场景**:
- 客户业务持续产生需求
- 客户有"长期可用资源"诉求
- 客户不想每次单独议价

**报价公式**:
```
月费 = (单次交付价 / 3) × 1.2–1.5
```

**为什么是单次的 1/3 而不是更低**:
- 订阅对客户有"锁定价值"
- 订阅让你收入可预测
- 订阅的客户流失率比一次性低

**常见形态**:
- 月度运维（系统维护、问题处理）
- 季度咨询（定期回顾、优化建议）
- 年度顾问（专属时间 + 优先级响应）

**优点**:
- 现金流稳定
- 客户黏性高
- 可叠加增值服务

**缺点**:
- 客户可能"用不完"觉得亏
- 需要持续提供价值，否则不续费

**关键技巧**:
- 月费不要"按工时算"，要"按价值算"
- 设定明确服务边界（多少小时响应、哪些不包含）
- 续费前 30 天主动回顾价值

---

## 模式 4: 陪跑（Coaching）

**形态**: 你不直接做，而是**边做边教**，客户主导，你指导

**适用场景**:
- 客户团队有人力但缺经验
- 客户想培养内部能力
- 客户业务高频发生，需要持续支持

**报价公式**:
```
价格 = 周期时长 × 周单价
周单价 = (人日单价 × 5) × 0.8–1.2
```

**为什么周单价不是 5 倍人日**:
- 你不是 100% 时间投入
- 但要保留时间响应客户问题
- 0.8 = 轻度陪跑（每周 1–2 次同步）
- 1.2 = 重度陪跑（每天响应）

**优点**:
- 客户主导，满意度高
- 客户学到能力，长期复用
- 你不用亲自下场做脏活

**缺点**:
- 客户决策慢，周期长
- 你"投入时间"但"产出归客户"
- 不适合急性子客户

---

## 模式 5: 分成（Revenue Share）

**形态**: 不收固定费，从客户业务流水中抽成

**适用场景**:
- 你有能力帮助客户增加收入
- 客户现金流不充裕但业务有前景
- 双方有长期信任基础

**报价公式**:
```
抽成比例 = 5–20%
抽成周期 = 3–12 个月
封顶 = 单次交付价的 3–5 倍
```

**优点**:
- 客户零启动成本，接受度高
- 你赚的是"价值"不是"工时"
- 长期绑定

**缺点**:
- 客户可能隐瞒真实收入
- 客户业务失败 = 你白干
- 需要明确结算方式（系统对账 vs 客户自报）

**关键技巧**:
- 必须有封顶，避免长期绑定
- 必须有结算依据，避免扯皮
- 必须可以提前终止，避免客户赖账

## 模式 6: 副业限定档 ⭐ 新增

**形态**: 利用业余时间（晚上/周末）交付，工期延长，单价降低，但严格限定范围

**适用场景**:
- 接单方是学生/科研人员/有本职工作的人
- 客户预算紧但接受业余节奏
- 单笔金额小（¥800–3,000）

**报价公式**:
```
价格 = 工时 × 副业单价(¥150–300/日) × 副业工期系数(1.5–2.0)
```

**副业限定档的核心特征**:

1. **业余时间声明**（必须）
   - "本项目利用业余时间（晚上/周末）交付"
   - "响应时间为工作时间外 4–24 小时"
   
2. **工期延长**（默认 1.5–2.0 倍）
   - 5 天活 → 7–10 天
   - 7 天活 → 10–14 天
   
3. **不含售后**（必写）
   - "交付后 X 天内验收"
   - "售后维护单独计费 ¥200/次"
   
4. **预付比例提高**（≥70%）
   - 副业风险高，必须先收钱再启动

**优点**:
- 接到更多单（低门槛）
- 利用闲置时间
- 积累案例和人脉

**缺点**:
- 单笔收入低
- 时间碎片化
- 不能接急单

**副业限定档的 3 个红线**:
- ❌ 不用主业资源（实验室 GPU、服务器）
- ❌ 不影响主业（老板的工作优先）
- ❌ 不接紧急单（响应时间承诺不了）

## 模式 7: AI 辅助档 ⭐ 新增

**形态**: 用 AI 工具（Copilot/Claude Code/ChatGPT）加速代码生成、debug、报告撰写，人工 review 关键环节

**适用场景**:
- 交付物以代码 / 数据 / 报告为主
- 客户接受 AI 辅助（必须明示）
- 工时压缩 30–60%

**AI 辅助档的核心特征**:

1. **AI 工具清单**（SOW 必列）
   - "代码生成: Claude Code / Copilot"
   - "数据处理: Python + AI 辅助脚本"
   - "报告撰写: AI 模板 + 人工 review"
   
2. **AI 加速比例**（按环节标注）
   - 代码生成: 80%
   - 数据处理: 70%
   - 报告撰写: 80%
   - 关键判断 / 实验验证: 0%
   
3. **人工 review 环节**（必写）
   - "AI 生成的所有代码必须人工 review"
   - "关键决策 100% 人工"
   - "幻觉数据必须人工核对"

**AI 增效后的定价策略**:

| 策略 | 工时系数 | 单价 | 最终报价 | 客户感知 | 你的收益 |
|---|---|---|---|---|---|
| A. 利润最大化 | 0.4 | 全职 ¥300/日 | 4 人日 × 300 = ¥1,200 | 副业价 | 高（60% 利润） |
| B. 平衡 ⭐ 推荐 | 0.5 | 副业 ¥200/日 | 4 人日 × 200 = ¥800 | 副业 + AI 让利 | 中 |
| C. 获客 | 0.6 | 副业 ¥150/日 | 4 人日 × 150 = ¥600 | 极致性价比 | 低（口碑投资） |

**AI 辅助档的 4 个合规红线**:
- 🔴 不能把客户数据喂给公网 AI（数据隐私）
- 🔴 不能 AI 代写论文方法学（学术不端）
- 🔴 不能 AI 幻觉数据（必须人工 review）
- 🔴 必须告诉客户"AI 辅助"（客户同意才能做）

**优点**:
- 工时压缩 30–60%
- 利润空间更大
- 交付更快（相对副业档）

**缺点**:
- AI 生成代码可能需多轮 review
- 数据隐私有合规风险
- 客户可能不接受 AI

## 打包方式选择决策树

```
客户是论文/专利类？
├── 是 → 学术服务分支（参考 academic-service.md）
└── 否 → 继续
    │
    接单方是副业身份？
    ├── 是 → 模式 6（副业限定档）+ 模式 7（AI 辅助档）组合
    └── 否 → 继续
        │
        客户说"以后还要调试/维护"？
        ├── 是 → 模式 2（能力转移）或 模式 3（订阅）
        └── 否 → 继续
            │
            客户业务持续产生需求？
            ├── 是 → 模式 3（订阅）或 模式 5（分成）
            └── 否 → 继续
                │
                客户有团队但缺经验？
                ├── 是 → 模式 4（陪跑）
                └── 否 → 模式 1（一次性）
```

**副业 + AI 组合的实际应用**:

```
典型组合: 模式 6（副业限定档）+ 模式 7（AI 辅助档）
适用场景: 学生 / 科研人员接单
报价公式: 
  价格 = (基础工时 × AI 加速系数) × 副业单价 × 副业工期系数
  价格 = (8 人日 × 0.4) × ¥200/日 × 1.5
  价格 = 3.2 × 200 × 1.5 = ¥960 ≈ ¥1,000
```

## 错误打包的典型场景

| 客户说 | 错误做法 | 正确做法 |
|---|---|---|
| "以后还要维护" | 模式 1 单次报价，1 万跑单 | 模式 2 能力转移，2 万成交 |
| "我们每月都有这种需求" | 模式 1 每次单独议价 | 模式 3 订阅，统一月费 |
| "我团队能做，就是不会" | 模式 1 全包 | 模式 4 陪跑，边做边教 |
| "预算紧，但做好了能赚大钱" | 模式 1 报低价 | 模式 5 分成，客户零成本 |
| "就这一次" | 模式 2 报高价 | 模式 1 报实价 |
| **"我是学生，晚上有空"** ⭐ | **模式 1 全职报价** | **模式 6 副业限定档** |
| **"能不能用 AI 加速？"** ⭐ | **模式 1 标准报价** | **模式 7 AI 辅助档** |
| **"学生 + AI 辅助"** ⭐ | **模式 1 报错** | **模式 6 + 7 组合** |
