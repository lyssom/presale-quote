# 价格区间计算（含副业档 + AI 增效）

## 核心原则

**永远给区间，不给单点。**
- 单点报价 = 客户没参考系 = 客户要么嫌贵要么嫌便宜 = 跑单
- 区间报价 = 客户有选择感 = 客户感觉"被尊重" = 提高成交率

**副业 + AI 增效场景特别原则：**
- 副业档定价起点更低（¥150–300/日）
- AI 增效后的工时压缩系数 0.3–0.7（不要直接转嫁给客户降价）
- 副业工期系数 1.5–2.0（业余时间节奏）

---

## 项目起点系数（最关键，先看这个）

**核心原则**：项目起点不同，工时差异巨大。**算工时前先判定起点。**

| 起点 | 系数 | 典型描述 |
|---|---|---|
| 从 0 开发 | 1.0 | "做个新系统/工具" |
| 基于成熟框架 | 0.7–0.8 | "用 FastAPI/SpringBoot 做个应用" |
| **基于开源项目改造** | **0.3–0.5** | "借鉴 GitHub 上的 XX 项目改一下" |
| 纯配置 / 数据替换 | 0.1–0.2 | "换个数据集、改个 prompt" |
| **基于预训练模型推理** | **0.2–0.4** ⭐ 新 | "用 MetGitX 预训练权重直接跑" |
| **AI 辅助全流程** | **0.3–0.7** ⭐ 新 | "AI 写代码 + 人工 review" |

**判定问题**：
1. 客户说"借鉴/参考/基于 XX 项目" → 开源改造，0.3–0.5
2. 客户说"用 XX 框架"但没说"参考具体项目" → 框架，0.7–0.8
3. 客户说"做个 XX"没提任何已有方案 → 从 0，1.0
4. 客户说"改一下 XX 数据/参数" → 配置/替换，0.1–0.2
5. **客户说"用预训练模型跑推理"** → 预训练推理，0.2–0.4 ⭐ 新
6. **客户接受 AI 辅助完成** → AI 辅助档，0.3–0.7 ⭐ 新

## 客户类型 × 单价矩阵（决定人日单价）

**核心原则**：人日单价不是固定的，要看客户来源。

| 客户来源 | 单价区间 | 议价空间 | 首单让利上限 |
|---|---|---|---|
| 接单群 / 个人客户 | ¥200–500/人日 | ±20% | 20% |
| 工作室直客（熟人介绍） | ¥500–1,000/人日 | ±15% | 15% |
| 中小公司正式单 | ¥1,000–1,500/人日 | ±10% | 10% |
| 长期合作老客户 | 按历史价 | ±5% | 5% |
| 资深顾问 / 复杂项目 | ¥1,500–3,000/人日 | ±10% | — |
| **副业接单（学生/科研人员）** | **¥150–300/人日** ⭐ 新 | ±20% | 30%（首单可压到 100） |
| **副业 + AI 增效** | **¥100–250/人日（实际成本）** ⭐ 新 | ±10% | 20% |

**判定问题**：
1. 客户在群里找你？→ 接单群档
2. 客户通过朋友/熟人介绍？→ 工作室档
3. 客户是企业、有公司主体？→ 中小公司档
4. 客户合作过 3+ 单？→ 长期客户档
5. **你是学生/科研人员副业接单？** → 副业档 ⭐ 新
6. **你用 AI 加速了核心交付？** → AI 增效档（实际成本更低，可让利换口碑）⭐ 新

**反例（错误定价）**：
- 副业学生接单按 ¥1,200/人日报价 → 客户跑了
- 副业学生实际成本 ¥150–250/人日（接单群 × 0.6）
- 同样 5 人日工作量，副业 ¥1,000，全职 ¥2,500

## 副业接单定价专项 ⭐ 新增

### 副业 vs 全职的定价差异

| 维度 | 全职接单 | 副业接单 |
|---|---|---|
| 时间机会成本 | 高（占用上班时间） | 低（晚上/周末，边际成本≈0） |
| 真实单价 | ¥200–3,000/人日 | ¥150–300/人日 |
| 工期系数 | 1.0（标准） | 1.5–2.0（业余节奏延长） |
| 预付比例 | ≥50% | ≥70%（副业风险高） |
| 售后 | 可包含（1 个月） | 不含 / 单独议价 |
| 单笔下限 | ¥3,000 | ¥800（副业起步价） |

### 副业 1000 元单的真实价值

不要按"工资"算，要按"投资"算：

| 项 | 价值 |
|---|---|
| 票面收入 | ¥1,000 |
| 案例价值 | ¥3,000–5,000（作品集） |
| 客户关系价值 | ¥5,000–20,000（长期复购） |
| 技能实操价值 | ¥2,000（学习） |
| **总价值** | **¥10,000–25,000** |

### 副业接单的 4 个红线

- ❌ 不用实验室资源（GPU、算力、服务器）
- ❌ 不影响主业（老板的工作永远优先）
- ❌ 不接紧急单（副业响应慢，承诺不了）
- ❌ 不让客户知道你是"专家"（会压价）→ 但要显得专业

| 策略 | 工时系数 | 单价 | 最终报价 | 客户感知 | 你的收益 |

## 报价反推公式（用于自检）

**已知客户预算时，反推合理报价**：

```
客户预算 < ¥1,000     → 报价 = 预算 × 1.5–2.5（基础功能，超出砍）
客户预算 ¥1k–5k      → 报价 = 预算 × 1.2–1.8（标准功能，含文档）
客户预算 ¥5k–20k     → 报价 = 预算 × 1.0–1.3（完整交付 + 培训）
客户预算 > ¥20k       → 报价 = 预算 × 0.8–1.0（议价空间小，按预算报）

副业场景下，预算可降低 30–50%：
客户预算 < ¥1,000     → 副业报价 = 预算 × 1.3–1.8
客户预算 ¥1k–3k      → 副业报价 = 预算 × 1.0–1.4
```

**接单群场景金标准**：报价 = 客户预算 × 1.5–2.0
**副业接单场景金标准**：报价 = 客户预算 × 1.3–1.8（让利空间更大）

## 基准定价：人日法

### Step 1: 估算工时（AI 增效后）

把交付物拆成最小工作单元，每个单元估工时，乘以 AI 加速系数。

**示例拆解**（AI+MS 预测场景，副业 + AI 辅助）：
```
1. 数据准备: 2 人日 × 0.3 = 0.6 人日
2. 环境搭建: 1 人日 × 0.5 = 0.5 人日
3. Baseline: 2 人日 × 0.3 = 0.6 人日
4. 微调实验: 5 人日 × 0.5 = 2.5 人日（必须人工 review）
5. 验证: 2 人日 × 0.5 = 1.0 人日
6. 报告: 1 人日 × 0.2 = 0.2 人日
7. 验收 buffer: 1 人日 × 0.5 = 0.5 人日
8. 副业工期延长: ×1.5 = 总计 ×1.5

基础工时: 5.9 人日
副业调整后: 5.9 × 1.5 = 8.85 人日
```

### Step 2: 选择人日单价（按客户类型）

| 客户类型 | 单价 |
|---|---|
| 全职接单群 | ¥250–400/人日 |
| **副业学生/科研人员** | **¥150–250/人日** |
| **副业 + AI 增效** | **¥100–200/人日**（实际成本压缩） |

### Step 3: 应用调整系数

| 系数 | 触发条件 | 调整 |
|---|---|---|
| 加急系数 | 工期 < 标准 70% | +10–30% |
| 复杂度系数 | 跨领域/高风险/需创新 | +20–50% |
| 试水系数 | 首单 / 客户试探 | -10–20% |
| 长期系数 | 后续复购明确 | -10–20% |
| 渠道系数 | 客户是分销/转介绍 | -10–30% |
| 风险系数 | 客户信誉不明 / 范围模糊 | +20–50% |
| **副业系数** ⭐ | 副业接单 | -20–40%（让利空间） |
| **AI 增效系数** ⭐ | AI 辅助完成 | -10–30%（让利或投资质量） |

**最终区间 = 基准价 × (1 + Σ系数)，再取 ±20% 形成区间**

## 锚点策略

### 锚点 1: 价值锚
不要说"我做 X 需要 X 天"，要说"这个能帮客户省 X / 赚 X"。

**示例**：
- "这个工具能让客户每月节省 20 小时，相当于 ¥4,000 人力成本"
- "这个方案能让客户业务效率提升 30%，按客单价算每月多收 ¥X"

### 锚点 2: 对比锚
找客户能感知的对比对象。

**示例**：
- "市面上同类全职服务报价 ¥3k–5k，我这边副业档 ¥1k，因为没有运营成本"
- "客户自己招人做需要 X 个月，按月薪 ¥Y 算也要 ¥30k+"

### 锚点 3: 成本锚
透明列构成，让客户知道"不贵"。

**示例**：
- "我这 4 人日 × 副业单价 ¥250 = ¥1,000，加 20% 风险 buffer = ¥1,200"
- "AI 辅助节省 60% 工时，但我不降价，让利空间投资到交付质量"

### 锚点 4: 风险锚
让客户知道"便宜的代价是什么"。

**示例**：
- "¥800 的是单工具 + 无报告；¥1,000 含 3 工具 + 报告；¥1,500 含 2 轮修改"
- "副业档工期 7–10 天，全职档 3–5 天，您选哪个？"

### 锚点 5: 副业专属锚 ⭐ 新

**示例**：
- "我是副业接单，工期比全职长，但价格只有全职团队的 30–50%"
- "性价比 = 专业度 × 业余时间让利，您拿到的是同样的专业水平，更低的价格"

## 调整系数的应用细节

### 加急系数怎么算

**标准工期 = 基础工时 × 1.5**（含 buffer）

- 客户要 ≥ 1.5 倍标准工期 → 不加价
- 客户要 1.0–1.5 倍 → +10–20%
- 客户要 0.5–1.0 倍 → +20–40%
- 客户要 < 0.5 倍 → +40%+ 或拒绝

**副业场景特别规则**：
- 副业不接加急单（业余时间没法压缩）
- 客户说"急" → 直接拒："副业接单响应慢，您找全职团队"

### 风险系数怎么定

| 风险类型 | 系数 |
|---|---|
| 客户是陌生个人，付款方式不确定 | +20% |
| 客户范围描述模糊 | +30% |
| 客户有特殊合规/法律要求 | +30–50% |
| 客户历史上拖欠款项 | +50% 或不接 |
| **副业接单 + 陌生客户** | **+20–30%** ⭐ 新 |
| **AI 辅助 + 数据敏感** | **+30–50%** ⭐ 新 |

### 长期系数怎么用

**首单让利的边界**：
- 让利 ≤ 20%: 健康，建立信任
- 让利 20–40%: 谨慎，确认客户真有意向
- 让利 > 40%: 危险，可能被白嫖或客户不珍惜

**判断标准**：
- 客户在群里活跃、互动多 → 真长期
- 客户只是路过、一次对话 → 假长期
- 客户能给出"后续需求清单" → 真长期
- 客户说不清后续 → 假长期

**副业首单让利边界**：
- 让利 30–50% → 健康（副业本来就是让利换案例）
- 让利 > 50% → 危险，可能被白嫖
- 让利必须换：客户好评 + 推荐 + 长期合作承诺

## 区间 vs 阶梯：何时用哪个

**用区间**：
- 客户预算灵活
- 交付物可拆分
- 你想让客户"自由选择"

**用阶梯**（3 档套餐）：
- 客户决策慢，需要"标准化选项"
- 你想推中高价档
- 交付物天然分基础/标准/高级
- **副业场景强烈推荐用阶梯** ⭐ 新（让客户自己选档位）

**阶梯模板（副业版）**：
```
【经济版】¥800
- 单工具结构 (CFM-ID 或 SIRIUS)
- 1 张谱图 Top-10 候选
- 不含报告
- 7–10 天交付

【标准版】¥1,000（推荐）
- 3 工具组合 (CFM-ID + SIRIUS + MetGitX)
- 1 张谱图 Top-10 候选
- 含 1 页 PDF 报告
- 7–10 天交付
- 1 轮修改免费

【完整版】¥1,500
- 3 工具 + 重排序
- 3 张谱图
- 含 3 页报告
- 14 天交付
- 2 轮修改免费
- 1 个月售后
```
